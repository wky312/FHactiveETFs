# Concept Brief: 每日行銷亮點引擎 ＋ 資金流與市占觀測

> 日期: 2026-07-05
> 狀態: Reviewed（方向已與使用者確認）；**同日更新：B 資金流分頁經使用者再評估後取消**
> 下一步: /feature-spec daily-highlight-engine（僅剩 A）

## 背景與動機

fhactiveetf.vercel.app 的設計目的是：①幫助行銷復華主動式 ETF 時有更多切入點與分析、②掌握同業競爭產品狀況。現有 13 個分頁在「觀測」上已有基礎（持股/軌跡/同業績效/同業申贖/歸因），但有兩個缺口：

1. **行銷切入點完全靠人眼從數據裡挖**——沒有任何功能主動告訴使用者「今天有什麼可以講」。
2. **競品觀測有單點查詢、缺聚合視角**——資金流只有當日表格，沒有市占趨勢、累積排行、受益人結構等行銷部真正關心的「錢流去哪」視角。

網站定位為**內部工具（行銷/投資團隊自用）**，功能可以直白服務素材產出；法遵在內容對外前才把關（可銜接 ad-compliance-checker / etf-content-factory）。

## 核心概念

**A. 每日行銷亮點引擎**：收盤後排程自動掃描所有既有數據源，依規則產出「今日亮點」（標題＋依據數據＋建議切入角度＋草稿句），**只推播到 LINE、不在網站上呈現**——網站會被其他人看到，行銷素材類內容僅私下推播。歷史結果存私有 repo（JSON）供調閾值與回顧。

**B. 資金流與市占觀測**：新「資金流」分頁聚合三個視角——AUM 市占率趨勢、累積淨申贖排行/連續申購 streak、TDCC 受益人數（趨勢、週增減排行、平均每人持有金額、級距分布）。

## 目標場景

- 每天收盤後，行銷同仁收到 LINE 推播：「00991A 是全市場主動 ETF 中持有 XX 最重的（4.2%），該股今日 +6%」→ 直接變成當天社群貼文／業務話術的切入點。
- 週會要講競品：打開資金流分頁，看誰的市占在掉、誰連續淨申購、我們受益人數週增幅排第幾。
- 主管問「主動管理的價值在哪」：從推播紀錄／私有 repo 的亮點存檔翻出「6/20 加碼的 XX 至今 +12%」等操作驗證實例。

## 探索過程摘要

### 研究發現
- **TDCC 集保戶股權分散表**（開放資料 `smart.tdcc.com.tw/opendata/getOD.ashx?id=1-5`）已實測可用：每週五更新、免 token、CSV 全市場；00991A 2026-07-03 受益人數 279,173（級距 17＝總計），另有 15 個持股級距可算散戶/大戶結構。**只回最新一週** → 需每週累積；歷史可用 TDCC 查詢頁（保留一年）一次性回補 ~52 週。
- 亮點引擎所需數據**全部已在手上**：fhtrust 持股、active-etf-tracker Supabase（19 檔全市場每日持股）、peer-performance（Yahoo）、peer_redemption（申贖/AUM）、個股日K。

## 收斂結論

### A. 每日行銷亮點引擎
- **範圍**：先 **00991A 單檔**驗證（台股檔、資料最齊、規則最好驗證），有感再擴 00998A／全產品線。
- **輸出**：**只有 LINE 每日推播**（沿用 etf-daily-line 的推播基建/模式），不做網站分頁——網站會被其他人看到，亮點內容不得出現在站上。歷史結果存私有 repo JSON（調閾值、回顧用）。
- **文案**：確定性模板為主（數據句不出錯、免 API）；Gemini 潤飾為選配。
- **候選規則**（可逐條上線，先挑 3 條最有感）：
  1. 重倉股表現（含「全市場主動 ETF 中持有最重」比較）
  2. 獨門持股事件（只有復華持有／權重顯著高於同業的股票大漲/創高）
  3. 操作事後驗證（近 N 日加碼股至今報酬；減碼後回跌＝躲過）
  4. 績效里程碑（MTD/YTD 排名、連續 N 日勝 0050、淨值創高）
  5. 資金流事件（連續淨申購 N 日、AUM 整數關卡、單日淨申購同業第一）
  6. 受益人數事件（週增幅同業第一、破整數關卡）——依賴 D 的 fetcher
- **架構**：收盤後 GitHub Actions（cron-job.org 觸發，沿用現有 pattern）跑掃描 script → LINE 推播 → 結果 JSON commit 回私有 repo 存檔。掃描邏輯可放本 repo（讀同一批 lib/資料源）但不掛任何前端路由。
- **不做**：網站「今日亮點」分頁（其他人會看到）；餵入 etf-content-factory（暫緩）；對外公開版法遵化呈現。

### B. 資金流與市占觀測（新「資金流」分頁）— ❌ 已取消（2026-07-05）

以下保留當時的設計探索紀錄。若日後重啟，spec 前已驗證：TDCC 查詢頁回補 51 週可行（無驗證碼、CSRF token 串接即可）；peer_redemption 僅覆蓋 12 檔，全市場市占可用 TDCC 週頻單位數×收盤價近似。TDCC weekly fetcher 若亮點引擎需要「受益人數事件」規則，可獨立實作、不依賴本分頁。
- **市占率趨勢**：各檔 AUM 佔全體主動 ETF 比重時間序列（資料源＝既有 peer_redemption），自動標記「市占新高」。
- **資金流排行**：本週/本月/YTD 累積淨申贖排行、連續淨申購天數 streak 榜。
- **受益人數**：新增 TDCC weekly fetcher（每週六抓、累積存檔）＋一次性回補 52 週；圖表＝趨勢、週增減排行、AUM÷人數（散戶滲透 proxy）、級距分布。
- **不做**：不動既有「規模」「同業申贖」分頁（降低改動風險），新分頁聚合新視角。

### 關鍵假設與風險
- TDCC 查詢頁回補 52 週的可行性（頻率限制/驗證碼）未實測——若不可行，接受「從現在開始累積」。
- peer_redemption 的 AUM 覆蓋度＝市占率分母品質；海外組部分檔已接通、tw_active 齊全。
- 亮點規則的「有感度」需實跑幾天調閾值，屬迭代成本非技術風險。

## 與現有系統的關係

- **資金流分頁**沿用 `Dashboard.tsx` 的 `Tab` union ＋ `components/*Tab.tsx`；inline style、Plotly CDN 慣例不變。**亮點引擎不新增任何前端路由/分頁**。
- 亮點引擎掃描 script 讀 active-etf-tracker Supabase 時沿用 attribution 的獨立唯讀環境變數 `ATTR_SUPABASE_URL/ANON_KEY`。
- 排程沿用「GitHub Actions ＋ cron-job.org 觸發、只 commit 不部署」模式；注意 **Vercel 未接 git 自動部署**，靜態存檔類資料要等手動 `vercel --prod` 才進 bundle → **TDCC 受益人數資料建議走 Supabase 或 API route 即時讀**，避開此限制（亮點結果不進網站、不受影響）。
- LINE 推播複用 etf-daily-line 的 channel/圖床經驗（該專案圖床在 CI 只有 tmpfiles 成功；亮點推播以文字為主可避開圖床問題）。
